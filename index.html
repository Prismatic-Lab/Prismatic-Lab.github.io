TECHNICAL OVERVIEW

Security lives inside the client.

SIVR extends the hack.chat protocol through an application-layer secure messaging protocol implemented entirely inside the client.

The protocol is designed to operate transparently over the standard hack.chat transport, allowing secure clients to communicate without requiring any changes to the existing server implementation.

Every encrypted message is authenticated before being displayed. Invalid signatures, replayed packets from trusted peers, malformed packets, and failed decryptions are rejected before reaching the user interface.

01

02

Ed25519

Digital signatures provide sender authentication and message integrity.

03

Stable identity

Client identity is backed by persistent cryptographic keys rather than temporary session identifiers.

04

TOFU verification

Trust-On-First-Use fingerprint verification establishes and recognizes trusted peers.

05

Replay protection

Trusted peer sequence tracking prevents previously accepted packets from being replayed.

06

Secure presence

Presence discovery is authenticated so clients can identify trusted peers securely.

07

State recovery

Automatic reconnection restores client state after temporary transport interruptions.

08

Verified rendering

Markdown content is rendered only after successful authentication and decryption.

✓

No server-side cryptography.

SIVR requires no cryptographic processing or protocol modifications on the server. Encryption, authentication, identity verification, replay protection and message validation remain inside the client.

README

Sivr in brief.

Sivr

Sivr is a privacy-focused, end-to-end encrypted chat client built on top of a lightweight relay-based infrastructure. It is designed to provide secure, authenticated communication while keeping message content inaccessible to the relay server.

The project places emphasis on client-side security, cryptographic identity verification, and protection against message replay and unauthorized access.

Core principles

  • Messages are encrypted before transmission.
  • Cryptographic identities can be verified through fingerprints.
  • The relay transports encrypted data without requiring readable message content.
  • Message sequencing provides replay protection.
  • Security-sensitive operations remain client-side.

Architecture

Sivr uses a client-centric security model. The client handles identity, encryption, authentication and message validation, while the relay primarily provides message transport.

Technical Overview

SIVR extends the hack.chat protocol through an application-layer secure messaging protocol implemented entirely inside the client.

  • End-to-end AES-256-GCM encrypted messaging.
  • Ed25519 digital signatures for sender authentication.
  • Stable client identity backed by persistent cryptographic keys.
  • Trust-On-First-Use (TOFU) fingerprint verification.
  • Replay attack protection using trusted peer sequence tracking.
  • Authenticated secure presence discovery.
  • Automatic reconnection with state recovery.
  • Markdown rendering after successful verification and decryption.
  • No server-side cryptography or protocol modifications.

Every encrypted message is authenticated before being displayed. Invalid signatures, replayed packets from trusted peers, malformed packets, and failed decryptions are rejected before reaching the user interface.
